# Pins and recent activity

Use the pin beside a project to keep it in **Pinned projects** above the other rows on every page. The **Pinned** sidebar filter shows just those projects. Pins respect search, status, and folder filters and do not count toward the page size. Click the pin again to remove it. Pinned projects are ordered by name.

**Recent activity** shows the last ten registered projects used through DevDock or its connected external tools. Recent projects appear before the remaining unpinned projects, newest first; each used project shows its last activity time. DevDock records successful starts and browser/folder opens. Pinning, viewing details, scanning, and failed actions do not create activity. A process successfully launched and subsequently crashed still counts as recently used. Opening a public preview does not update local activity. External bridges report workspace opens, agent events, editor focus, and PowerShell prompt activity; idle heartbeats do not refresh recency.

Pins and activity timestamps survive rescans and app restarts. Activity history does not restore a running server. Metadata is attached to the registered project path; removing its registration, excluding an inactive project, replacing the catalog during folder import, or clearing the discovery cache removes its pins and history. Preference resets retain them. Portable settings exports omit them; a full state backup includes them.

Existing saved catalogs start unpinned with no activity history. Optional `pinned` and `lastActiveAt` fields are added to project metadata in saved-state v3. Strict writes reject malformed values; damaged optional activity values are ignored when loading, preserving the valid catalog. Scan commits merge these fields from the latest saved state so concurrent pin/activity changes survive discovery. Runtime snapshots overlay saved fields even while launch metadata is retained by a running process.

Connect VS Code, Codex, Claude Code, and PowerShell under **Settings → External activity**. Source badges indicate reported open sessions or agent work; unverified agent owners show only a brief **recent** badge. The **Active** filter and count reflect servers that are starting, running, unverified, stopping, or still managed by DevDock. Open tool sessions with stopped servers remain in **Recent activity**. Detected servers started elsewhere show their actual URL with **Running elsewhere**, **Open**, and **Stop external server**. Stop ends the verified server and workers while keeping its editor and terminal open; Restart remains disabled. After stopping, use Start to run the project through DevDock or launch it again in its original terminal. Start checks for external servers before launching to prevent duplicates. See [external activity](external-activity.md) for setup, supported tools, output capture, and validation limits.

## Validation

`npm.cmd run test:projects` uses real Electron with isolated user data and generated static sites. It checks keyboard pinning, pins across pages, filtering/search, recent ordering, browser/folder/start events, failed opens, invalid IPC, rescans/relaunches, unpin persistence, small-window layout, and light/dark screenshots. Browser/folder openers are stubbed; no user projects or external apps are operated. Vitest covers durable saves, concurrent scans, runtime metadata, malformed fields, launch failure, the recent limit, and portable remembered filters.
