## Result

Running local projects can create independent temporary public HTTPS links through Cloudflare Quick Tunnels. HTML links preserve the selected entry page. A short confirmation includes read-only compatibility hints. Copy Public Link, Open Public Link, Stop Sharing, and Stop All Sharing distinguish local/public controls.

Sharing is explicit and never restored. Stop Sharing preserves local servers; stop/restart/crash and normal manager quit end associated sessions. Duplicate requests, cancellation, deadlines, ownership loss, and failed cleanup are handled separately from local status. At least three concurrent sessions are validated with generated fixtures.

Official Windows x64 cloudflared 2026.9.3 is pinned, checksum-verified, and prepared locally. Fresh checkouts run `npm.cmd run setup:sharing`. Disabled sharing does not contact the provider/download software. SavedState remains v2 with no migration.

## Validation and limits

**90 tests passed across 5 files.** Typecheck, lint, production build, compiled/development desktop smoke, and the real controlled three-project public run passed. Dedicated checks cover cleanup races and mixed IPv4/IPv6 ownership. Detailed behavior, evidence boundaries, and troubleshooting: [Public sharing](../public-sharing.md).

- PC, manager, local server, and internet must stay available; URLs change between sessions.
- Quick Tunnels have no uptime guarantee, a 200 in-flight-request limit, and no SSE.
- Preview intent does not make served routes/actions read-only.
- Next dev-origin rules, separate API ports, login/cookies/redirects, and custom HMR may need project changes. Existing project configuration/source was not rewritten.
- Only generated demos were publicly tested. Independent visitor-network verification remains pending because the external web reader could not access the temporary URLs.
- No universal Astro/custom-app, private business-workflow, forced-termination/power-loss, or disconnected-machine proof is claimed.
- No installer/distribution assets were produced; packaging/notice/resource-path validation is separate.
